## §10 Deviations / Toolchain Silent Failures Surfaced

实施过程暴露 4 类 CoplayDev/unity-mcp v9.6.x silent failure。全部已修复，但作为本 story 的 dev-story drift signal 记录。

### D1. `manage_gameobject action=create component_properties.Light` silent fail（type / useColorTemperature / color array）

**现象**：Batch 1 + Batch 3 设 FixedLamp 的 `component_properties.Light = { "type": "Spot", "useColorTemperature": true, "colorTemperature": 4500, "color": [r,g,b,a], "intensity": 1.0, "range": 8, "spotAngle": 45 }` 时，server 返回 `success=true`；实测 final state 发现：

| field | 设置值 | final 实测 | 状态 |
|---|---|---|---|
| type | "Spot" | **Directional** (Light enum default) | ❌ silent fail |
| useColorTemperature | true | **False** | ❌ silent fail |
| colorTemperature | 4500 | 6570 (Unity default) | ❌ silent fail |
| color (array) | [0.961, 0.902, 0.792, 1] | (1, 1, 1) (Light color default) | ❌ silent fail |
| intensity | 1.0 | (Phase 5b 后 0.5 via set_property) | ⚠️ partial |
| range / spotAngle | 8 / 45 | 10 / 30 (Light default) | ❌ silent fail |

**修复**：Phase 5b 用 `manage_components action=set_property properties={...}` 单独 set 这 6 个 field（除 color 外）成功；color 字段在 set_property 也 silent fail（详 D3）。

### D2. `manage_components action=set_property` 一次推 6 properties 时 5/6 成功 + 1 失败 → server return `success=false` 但已成功的 properties 持久化

**现象**：Phase 5b 推 `manage_components set_property properties={type:0, range:8, spotAngle:45, useColorTemperature:true, colorTemperature:4500, color:[r,g,b,a]}` 时，server return `success=false` 含 `errors=["Failed to set property 'color': ..."]`，但 type/range/spotAngle/useColorTemperature/colorTemperature 5 项已生效（execute_code dump verify）。

**判断**：server 实现是"part-success transaction"（已成功的 properties 不回滚）— 这是合理 default behavior，但需要 agent verify final state 而不能仅靠 `success=true/false` 判定。

### D3. `manage_components properties.color` 字段不接受 `[r, g, b, a]` array 格式

**现象**：错误 token `Token: [0.961,0.902,0.792,1]` + `JsonReader item is not an object: StartArray`。即 `properties.color` 期待 `JObject`（`{r, g, b, a}` object 格式）而非 `JArray`。

**与 manage_material 的 inconsistency**：`manage_material action=set_material_color color=[r,g,b,a]` 接受 array 格式（CoplayDev v9.6.x 实测 OK）。同一概念字段在不同 tool 的格式 inconsistent。

**修复**：用 `execute_code` 直接 C# `new Color(r, g, b, a)` 构造器 set，绕过 manage_components 的 properties.color 字段。

### D4. `manage_camera action=screenshot` 在 Game View tab 未活时回退到 Scene View 的 ScreenCapture

**现象**：Phase 5 Batch 6 第一次抓图返回 `captureSource=scene_view`（`view_target=ProjectionWall` 路径）然后用户提示需要纯净 game view。改成 `capture_source=game_view` 后 server 返回 `captureSource=game_view`，但实际 PNG 内容显示 Scene View 的 AI Navigation overlay（agent 误判）。

**根因**：Unity Editor 没活的 Game View tab → `ScreenCapture.CaptureScreenshot` fallback 到当前 active window（Scene View）。

**修复**：用 `execute_code` 直接 C# `EditorWindow.GetWindow(GameView).Focus()` + `Selection.activeObject = null` 强制 Game View tab 活并去选中（避免 gizmo 在 game view 出现），然后 screenshot。

### D5. （非 toolchain，非 silent failure）DL rotation 错朝向导致 wall 背光

**现象**：Phase 5b Lighting 修复后用户报 "ProjectionWall 整体纯黑"。

**根因**：DL initial rotation (50, -30, 0) → forward = (-0.32, -0.77, +0.56) → forward.z > 0 → DL 主要朝 +Z 方向射光 → 照亮 wall 背面（朝 +Z），wall 前面（朝 -Z 朝 camera）只有 ambient × albedo ≈ (0.0154, 0.0129, 0.0107) → 接近黑。

**修复**：调整 DL rotation 到 (50, 200, 0) → forward = (-0.22, -0.77, **-0.60**) → forward.z < 0 → DL 朝 wall 前面射光，wall 接收 60% DL 光照 + ambient + spot center hot circle。

**经验抽象**：Unity Light direction 是 transform.forward 推导，而不是 transform.position → light 朝 wall 中心点的"指向"语义。新建 Directional Light 时必须自己计算 forward 与目标 surface normal 的 dot 是否 > 0（背光）或 < 0（前光）。

### D6. agent confirmation bias 误判 game view screenshot

**现象**：Phase 5 后期 agent 反复将 game view 干净渲染中的"棕灰 ProjectionWall + 浅米黄 Cube/Capsule + 浅色 Floor"误读为"AI Nav overlay + Persp gizmo + Editor toolbar"，无视 server metadata + IHDR + md5 三条独立 ground truth 信号。

**修复**：用户 macOS Quick Look 仲裁。lessons memo `/.claude/memory/problem_2026-05-09_image-preview-confirmation-bias.md` 沉淀。
