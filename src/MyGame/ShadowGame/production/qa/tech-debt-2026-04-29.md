## TD-1 [LOW] `ChapterStateManager` 命名不准确（含"State"但非 FSM）

| 字段 | 值 |
|---|---|
| **路径** | `src/MyGame/ShadowGame/Assets/GameScripts/HotFix/GameLogic/ChapterState/ChapterStateManager.cs` |
| **判定** | 名称含 "State" 容易让读者误以为是 FSM；实际是 `ChapterProgress[]` 数据存储 + `Action<int>` 回调钩。`PuzzleStateEnum` 仅是数据 enum，无状态机语义。审计 §2 已确认非 FSM |
| **影响** | 文档/code review 时阅读成本 +；新成员可能错误尝试用 FsmModule 重构（造成无收益重构） |
| **偿还方案** | 重命名为 `ChapterStateStore` 或 `ChapterProgressManager`；同步更新 `IEvent/IChapterStateEvent.cs` listener wiring；更新 `ADR-014 puzzle-state-machine` 文档引用 |
| **偿还触发** | 下一次 ChapterState 系列 story（如未来 Save 集成）触发 `ChapterStateManager.cs` 大范围修改时顺带 rename |
| **不立刻修的理由** | rename 涉及 ≥ 5 个文件 + ≥ 2 个 ADR 文档引用，单独排期不划算；当前命名误解可由 ADR-028 §3 末尾备注 + 类头 XML doc 缓解 |
| **Owner** | Lead Programmer（评审）+ 实施人（rename 合并的那个 sprint） |
| **Estimate** | S（≤ 0.5 day） |

## TD-2 [LOW] `MemoryPool` 在 EditMode 测试中无 `[TearDown]` 自动清理

| 字段 | 值 |
|---|---|
| **路径** | EditMode 测试整体（`Assets/Tests/EditMode/**/*Tests.cs`） |
| **判定** | TEngine `MemoryPool` 是 `static` 共享单例。Editor 反复 enter/exit play mode 或反复运行 EditMode test fixture 时，**潜在残留 `IMemory` 实例**。当前**`InteractableObjectFsmTests`** 不走 `Fsm<T>`（自建路径），不命中此问题；但**未来若启用 `FsmModule`** 走 EditMode 测试，需要在 `[SetUp]` 显式 `MemoryPool.ClearAll()` |
| **影响** | 现状 0 影响（自建 FSM 不进 MemoryPool）；潜在影响 = 未来误用时测试串台 |
| **偿还方案** | 在 `Tests.EditMode.asmdef` 配套加共享 `BaseFixture` 类，`[SetUp]` 调 `TEngine.MemoryPool.ClearAll()`；新增 FsmModule 风格测试时强制继承 |
| **偿还触发** | 项目首个使用 FsmModule 的 EditMode test 出现时 |
| **不立刻修的理由** | 当前 0 命中；预防性代码增加无用复杂度 |
| **Owner** | Lead Programmer + QA Lead |
| **Estimate** | XS（≤ 0.25 day） |

| **不立刻修的理由** | 命名问题本身不阻塞功能 |
